2. Основная идея 

Guide_AI_Bot — это Telegram-бот для общения с ИИ (встроенный чат),
с возможностью подключения дополнительных интеллектуальных модулей: 

    продвинутый гороскоп,
    батлы агентов,
    биллинг и пополнение,
    викторина, переводчик, генерация изображений (для premium),
    и другие функции.
     

Пользователь взаимодействует с ботом в двух режимах: 

    Free — базовая модель (например, Mistral AI API);
    Premium — улучшенная модель через OpenRouter API.
     

 
3. Пользовательская логика 
3.1. При запуске (/start) 

    Бот приветствует пользователя.
    Отображает inline-кнопку “📋 Меню” (InlineKeyboardButton).
    Пользователь может сразу писать сообщения — всё, что не является командой, уходит в дефолтный чат с ИИ.
        (Уточнение v3.5): Если current_module отличается от chat, то сообщение может быть перенаправлено в активный модуль или выдано предупреждение пользователю о текущем состоянии.
         
    (Уточнение v3.5): При первом запуске бота, если consent не предоставлено (или NULL), бот запрашивает согласие пользователя на хранение и обработку его данных в соответствии с политикой конфиденциальности (ссылка на политику может быть предоставлена в сообщении запроса). Отказ может ограничить функционал или завершить взаимодействие.
     

Пример сообщения: 

🤖 Привет! Я Guide_AI_Bot.
Ты можешь просто начать писать — я отвечу как ИИ.
Чтобы увидеть все функции — открой меню:
[📋 Меню]

Для продолжения использования бота, пожалуйста, подтвердите согласие на обработку персональных данных. [Да] [Нет]
 
 
 
3.2. Меню (в стиле BotFather) 

По нажатию на кнопку “📋 Меню” бот отправляет сообщение с компактным текстовым меню: 

🤖 Guide_AI_Bot — главное меню
Текущий режим: 🟢 Free
/ai_chat — Чат с ИИ
/horoscope — Продвинутый гороскоп
/battle — Батл агентов
/balance — Баланс и пополнение
/settings — Настройки
/premium — Включить Premium
/free — Бесплатный режим
/quiz — Викторина на основе ИИ
/translate — Переводчик
/image_gen — Генерация изображений (premium)
/lang — Выбор языка
/referral — Реферальная программа
/back — Выйти из текущего модуля (если активен)
 
 

    Команды выглядят как кликабельные ссылки — Telegram подставляет их в поле ввода. Обработка ошибок ввода (например, опечатки).
    Пользователь нажимает команду, затем Enter — бот переходит в соответствующий модуль.
    (Уточнение v3.5): Команда /back (или /menu) должна быть доступна в меню и в логике модулей для возврата в основной чат (режим current_module = 'chat'). Возврат может быть инициирован модулем по завершению своего действия или по команде пользователя.
    После завершения работы модуля (или по команде /back) пользователь возвращается в чат (по умолчанию).

Бот при старте и в меню отображает текущий режим: 

    🟢 Free — бесплатный (лимит 50 сообщений/день);
    🟣 Premium — платный (unlimited + приоритет).
     

Режимы можно переключать через меню (/premium, /free).
(Уточнение v3.5): Переключение режимов может сбрасывать историю чата (если это логично с точки зрения UX и бизнес-логики), но не обязательно. 
 
3.4. Поведение сообщений 

    Любое сообщение, не начинающееся с /, идёт в модуль, указанный в current_module (по умолчанию chat).
    При переключении в другой модуль (/horoscope, /battle, …) current_module обновляется, и сообщения пользователя обрабатываются соответствующим модулем до возврата.
    (Уточнение v3.5): Контекст диалога (в chat_history) сохраняется в базе. Логика ограничения последними 20 сообщениями должна быть реализована при выборке данных для запроса ИИ (например, через ORDER BY created_at DESC LIMIT 20 в обратном порядке). Удаление старых записей из БД может быть реализовано отдельным фоновым процессом или триггером/очисткой по мере добавления новых, чтобы избежать накопления бесконечной истории.
    (Уточнение v3.5): Для голосовых сообщений (message.voice) предусмотреть обработку: распознавание речи (например, через speech_recognition или API Whisper) -> текст -> передача в текущий модуль/ИИ. Результат распознавания также сохраняется в chat_history.
    (Уточнение v3.5): Ввод пользователя должен проходить базовую проверку на наличие потенциально вредоносного контента перед отправкой в ИИ или выполнением команд модуля.

5. Работа с ИИ 
Free Mode 

    Используется внешняя модель (например, Mistral AI API).
    Ограничение на длину контекста и частоту запросов (Rate Limiting).
    (Уточнение v3.5): Реализовать fallback-логику при ошибках API ИИ (например, возврат сообщения об ошибке пользователю, повторный запрос, переключение на другую модель, если возможно). Логировать ошибки ИИ.
     

Premium Mode 

    Работа через внешний OpenRouter API (GPT, Claude и т.п.).
    Расширенный контекст и функции. Интеграция RAG для улучшения.
    (Уточнение v3.5): Также должна быть реализована fallback-логика.

7. Меню и расширение функционала 

    Меню формируется динамически из списка menu_items (например, из файла конфигурации или таблицы в БД).
    (Уточнение v3.5): Для добавления нового пункта меню и функционала нужно:
        Создать файл модуля в /modules/, наследуясь от BaseModule (или следуя протоколу).
        Реализовать основную логику обработки сообщений/действий.
        Зарегистрировать команду и обработчик в core/module_loader.py или в menu_builder.py.
         
    Не требуется изменять основной код (main.py).
    Реферал-система: /referral для бонусов. (Уточнение v3.5): Подробная логика (начисление бонусов, отслеживание рефералов) требует отдельной проработки и отражения в БД (например, таблица referrals).
     

 
8. Оплата и биллинг (MVP) 

    (Уточнение v3.5): Использовать систему прямых платежей через Robokassa API (не встроенные Telegram Payments). Это позволит использовать кастомную систему баланса и избежать комиссии Telegram.
    (Уточнение v3.5): Реализовать отдельным модулем /modules/balance.py.
    (Уточнение v3.5): Настроить webhook от Robokassa для подтверждения успешных платежей и обновления баланса пользователя в БД.
    Хранить баланс пользователя в таблице user_balance. Уведомления о низком балансе (например, < 10 RUB).
     

 
9. Админ-панель (MVP)

    списка пользователей,
    текущих режимов,
    статистики по диалогам (например, общее количество сообщений, уникальные пользователи),
    истории оплат (если реализовано).
    (Уточнение v3.5): Также может отображать статистику по модулям (сколько раз использовался каждый модуль).
     

Аутентификация: Кастомная (на Flask-Login или JWT, с отдельным endpoint /admin/auth для изоляции от API проекта на CodeIgniter).
